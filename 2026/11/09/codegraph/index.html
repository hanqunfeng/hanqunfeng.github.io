Codegraph 使用手册：给 AI Agent 的本地代码知识图谱

摘要

  • 本文写 CodeGraph 的安装、把 MCP 接到 Cursor 等 Agent、给项目建索引，以及日常用 codegraph_explore / CLI 查符号、调用链和改动影响面。索引落在项目本地的 .codegraph/，不上传代码。
  • 操作环境按 macOS，CLI 按 @colbymchenry/codegraph 1.6.2。Linux / Windows 安装命令一并给出；Agent 侧以 Cursor 为主，顺带覆盖 Claude Code、Codex CLI、opencode 等安装器支持的目标。
  • Get Started，Installation，CLI，MCP Server，Integrations。同系列流量追踪见 记录 Claude Code、OpenCode、Codex-Cli 的 请求/响应 数据。

它解决什么问题

Agent 要搞清「请求怎么到数据库」「改这个函数会砸到谁」时，通常会反复 grep、glob、Read，把调用链自己拼出来。CodeGraph 先把仓库解析成一张本地知识图谱（符号、调用边、依赖），再通过 MCP 把相关源码、调用路径和影响范围一次交回去。

图存在项目下的 .codegraph/（SQLite），解析用 Tree-sitter / Rust 内核，默认不碰 node_modules、dist 等依赖与构建目录，也遵守 .gitignore。没有 API Key，代码不离开本机。

默认 MCP 只暴露一个工具：codegraph_explore。官方测量里，一个强工具比一长串窄工具更不容易选错，也更省会话上下文。其余工具仍可用 CLI，或用环境变量重新挂上 MCP。

接到 Agent

装好 CLI 还不够：必须再跑一次安装器，把 codegraph serve --mcp 写进各 Agent 的 MCP 配置。这一步只接线，不建索引。

交互安装：

它会探测本机已装的 Agent，询问写全局还是只写当前项目，并写入 MCP 配置。支持的目标包括 Claude Code、Cursor、Codex CLI、opencode、Hermes Agent、Gemini CLI、Antigravity IDE、Kiro，以及 GitHub Copilot（VS Code / Copilot CLI / JetBrains）。

对 Claude Code、Codex CLI、Gemini CLI、opencode，安装器还会在 CLAUDE.md / AGENTS.md / GEMINI.md 里加一小段带标记的 CodeGraph 说明，方便子 Agent 或非 MCP 场景改用 codegraph explore。Cursor 等以 MCP 配置为主。这些写入可用 codegraph uninstall 干净拆掉。

非交互示例：

选项 取值 作用
--target auto、all、none，或逗号列表如 cursor,claude 选哪些 Agent；不加则交互询问
--location global 或 local 全局配置还是项目内配置
--yes 布尔 跳过询问，按默认值走
--init 布尔 接线后对当前目录执行 codegraph init
--no-permissions 布尔 不写 Claude Code 的自动放行列表
--print-config <id> 如 cursor、claude 只打印片段，不写文件

改完配置后重启 Agent（Cursor 整窗重启一次），MCP 子进程才会加载新配置。

已初始化时会看到文件数、按语言统计、节点 / 边数量等。未初始化时提示 Not initialized，并建议执行 codegraph init。

.codegraph/ 里通常有忽略规则，避免把数据库提交进 Git；目录本身可以按团队约定决定是否纳入仓库。只在本机用、不想在 git status 里看见相关文件时，按官方文档调整忽略规则即可。

codegraph install 和 codegraph init 分工不同：前者改 Agent 的 MCP / 说明文件，后者只服务当前项目的图。只装 CLI、或只接线不 init，Agent 都拿不到可用索引。

日常怎么用

在 Agent 里：默认用 codegraph_explore

有索引之后，问结构、流程、改动影响时，应直接让 Agent 调 codegraph_explore，而不是再开一轮 grep / Read 拼图。适合的问法例如：

  • 「UserService 怎么工作」

  • 「登录请求从路由到数据库的路径」

  • 「改 AuthMiddleware 会影响哪些调用方」

  • 查询里直接点名文件或符号，拿到带行号的源码片段

一次调用通常带回：相关符号的源码（按文件分组）、符号之间的调用路径（含回调、React 重渲染、JSX 子组件等静态分析能接上的动态跳转），以及对依赖面的摘要。Agent 应把返回内容当作已经读过，不要再用 grep 复核同一批结果。

刚改过的文件若还在监视器的防抖窗口里（默认约 2 秒），响应开头可能出现「某些文件尚待 sync」的提示。被点名的文件用内置 Read 看磁盘上的最新内容；未点名的待同步文件只会落在页脚说明里。

工作区根没有索引时，仍可通过工具参数 projectPath 去查另一个已 init 的路径（monorepo 里某个子服务、或第二个仓库）。路径上没有图时，工具会提示改用内置工具，而不会硬失败。

索引维护

Agent 通过 MCP 启动 serve --mcp 之后，监视器会在源文件增删改后防抖同步。多数时候不用手跑：

防抖间隔可用 CODEGRAPH_WATCH_DEBOUNCE_MS 覆盖，默认 2000，夹在 100～60000 毫秒。构建或格式化会短时间写很多文件时，可以调到 5000 或 10000，合并成一次 sync。

禁用共享后台进程时设 CODEGRAPH_NO_DAEMON=1；这时每个 serve --mcp 各自写索引，同一项目不要并行开多个 writer。

常见问题

  • 提示未初始化：在项目根执行 codegraph init，再用 codegraph status 看是否有统计输出。

  • MCP 连不上：确认 codegraph 在 Agent 进程能解析到的 PATH 上；Cursor 配置里带有 --path；改完配置后已重启。仍不行就再跑一次 codegraph install 重写配置。

  • 找不到符号：等一两秒让监视器 sync；或手跑 codegraph sync。确认文件扩展名受支持，且不在默认排除目录或 .gitignore 内。

  • database is locked：优先升级到带自带运行时的版本（本文的 1.6.2 已是该路线）。codegraph status 里 Journal 若不是 wal，常见于网络盘或 WSL2 的 /mnt 路径，把项目（含 .codegraph/）放到本地磁盘。

  • 同一项目多个 serve --mcp 抢写：保留默认 daemon，让多个宿主共用一个监视进程；若设了 CODEGRAPH_NO_DAEMON=1，同一项目只保留一个 writer。

  • Windows 与 WSL 共用一份检出：不要共用同一个 .codegraph/。WSL 侧可用 CODEGRAPH_DIR=.codegraph-wsl 再 init，两边各管各的索引。

命令速查

命令 含义
codegraph install 把 MCP 接到各 Agent
codegraph uninstall 从 Agent 拆掉配置（可加 --keep-cli）
codegraph init 创建 .codegraph/ 并全量建图
codegraph uninit 删除项目的 .codegraph/
codegraph index / sync 全量重建 / 增量同步
codegraph status 索引统计与健康情况
codegraph explore / node / query 探索、读符号、搜名称
codegraph callers / callees / impact 调用方、被调用、影响面
codegraph affected 按变更文件找受影响的测试
codegraph cycles 列出文件间循环 import
codegraph upgrade / version 升级 / 看版本
codegraph telemetry on|off 匿名遥测开关

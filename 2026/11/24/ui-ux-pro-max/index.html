UI/UX Pro Max 使用手册：给 Coding Agent 的可检索设计情报

摘要

  • 本文写 nextlevelbuilder/ui-ux-pro-max-skill：它如何用本地 CSV 知识库 + Python 检索脚本，在做界面前先生成可落地的设计系统，以及安装、升级、四端用法与常用检索命令。
  • 操作环境按 macOS，安装器按 npm ui-ux-pro-max-cli 2.15.0（命令仍是 uipro）。需要本机 Python 3。四端举例（命令行侧）：Claude Code、OpenCode、Codex CLI、Cursor；不含 Codex App。
  • 仓库与站点：GitHub，uupm.cc，ui-ux-pro-max-cli (npm)。同系列见 Superpowers 使用手册：给 Coding Agent 的强制开发工作流、Codegraph 使用手册：给 AI Agent 的本地代码知识图谱。

它解决什么问题

Agent 做落地页、仪表盘、组件时，常会落到一套「通用好看」的默认视觉：紫粉渐变、系统字体、卡片堆叠、图标用 emoji。产品类型不同，该有的风格、配色、字体、版式和反模式并不相同；靠模型临场发挥，跨页面也难一致。

UI/UX Pro Max 把设计决策做成 可检索的本地数据库 + 推理引擎，再以 Agent Skill 的形式挂到各宿主上。你提一个 UI 需求时，Agent 应先跑检索（尤其是 --design-system），拿到风格、配色、字体、版式、动效与「不要做什么」，再写代码；交付前对照清单查可访问性、触控、对比度等。

和 Superpowers 使用手册：给 Coding Agent 的强制开发工作流 分工不同：Superpowers 管「先想清楚再写、TDD、评审」等流程；本技能管「界面看起来怎样、交互是否合格」。两者可同时装。

2.0 怎么工作

核心是 Design System Generator。一次典型调用大致是：

  1. 从你的描述抽出产品类型、受众、风格关键词、技术栈。

  2. 并行检索多个域：产品类型、风格、配色、落地页结构、字体配对等。

  3. 用 ui-reasoning.csv 里的行业规则做匹配与过滤（含反模式）。

  4. 输出一整套设计系统：Pattern、Style、Colors、Typography、Effects、Avoid、Pre-delivery Checklist。

对本机已装技能跑 beauty spa wellness 的 --design-system -f markdown 时，会给出 Soft UI Evolution、具体色板、标题/正文字体、应避开的霓虹色与生硬动效，以及交付前核对项。Agent 应把这份输出当作后续实现的硬约束。

数据与脚本装在 skill 目录里（data/*.csv、scripts/search.py），默认不上传你的项目代码。检索在本地用 Python 跑。

能力概览

按上游 2.0 公开说明（数量随版本浮动，以你装到的包为准）：

类别 内容
UI 风格 约 67 种（通用 / 落地页 / BI 仪表盘等）
配色 约 161 套，与产品类型对齐
字体配对 约 57 组，含 Google Fonts 引用
UX 指南 约 99 条（无访问性、触控、动效、表单等）
图表 约 25 类推荐
推理规则 约 161 条行业规则
技术栈 React、Next.js、Vue、Nuxt、Svelte、Astro、HTML+Tailwind、shadcn/ui、SwiftUI、React Native、Flutter、Jetpack Compose 等

规则优先级从高到低大致是：可访问性 → 触控与交互 → 性能 → 风格选择 → 布局响应式 → 字体与颜色 → 动效 → 表单反馈 → 导航 → 图表。做 review 时可按这个顺序扫。

何时启用 / 何时跳过

必须启用： 新页面或大改版；新建 / 重构组件；选配色、字体、间距、布局；做 UI 代码的体验 / 可访问性检查；定导航、动效、响应式；产品级视觉与品牌表达；提升界面观感与可用性。

建议启用： 「不够专业」但说不清原因；可用性反馈落地；上线前 UI 质量过一遍；跨 Web / iOS / Android 对齐；搭设计系统或组件库。

可跳过： 纯后端、只改 API / 库表、与界面无关的性能、基建 / DevOps、非视觉脚本。

判断标准：任务会改变功能的 样子、手感、动效或交互方式 时，就应加载本技能。

日常工作流（Agent 侧）

装好后，多数时候你只需用自然语言描述产品与页面。Agent 应按 skill 说明走：

  1. 分析需求 — 产品类型、受众、风格词、技术栈。

  2. 生成设计系统（必做） — 先 --design-system，再写大段 UI。

  3. 按需补检索 — 某一域不够细时再 --domain / --stack。

  4. 实现 — 按输出的色板、字体、间距与栈指南写代码。

  5. 交付前核对 — 无 emoji 图标、可点击有 cursor-pointer、对比度、焦点环、prefers-reduced-motion、断点等。

检索命令（search.py）

search.py 是技能自带的本地检索入口：在 CSV 知识库里按关键词查风格、配色、字体、UX 等，或一次生成完整设计系统。Agent 做 UI 前应先跑它；你也可以在终端自己跑，核对输出。

在项目根执行。脚本路径随宿主变化；下面以 Claude 项目安装为例（Cursor / OpenCode / Codex 把 .claude/skills/... 换成对应目录）。参数以 ui-ux-pro-max-cli 2.15.0 打包的 search.py --help 为准；旧市场插件里的脚本选项可能更少。

查看本机帮助：

命令长什么样

通用形态：

  • 位置参数 query（必填）：自然语言或关键词，决定匹配哪一类产品 / 风格 / 主题。写英文短语效果通常更稳，例如 "beauty spa wellness"、"fintech banking"。

  • 不加 --design-system 时：按 --domain 或 --stack 做单域 / 单栈检索，返回若干条命中（默认最多 3 条）。

  • 加 --design-system 时：并行查多个域，再按推理规则合成一整套 Pattern / Style / Colors / Typography / Effects / Avoid / Checklist，打印到终端（可选再 --persist 落盘）。

参数一览

参数 简写 作用
query （位置参数） 搜索词；设计系统与单域检索都靠它匹配
--design-system -ds 生成完整设计系统（多域 + 推理）；与单域 --domain 检索不同
--project-name -p 设计系统输出里的项目名；配合 --persist 时还会参与目录名
--format -f 设计系统打印格式：ascii（默认）或 markdown；有 --json 时忽略
--persist 把设计系统写入磁盘（见下节目录结构）
--page 在 --persist 时额外写页面覆盖文件，如 dashboard
--output-dir -o --persist 的根目录，默认当前目录；应指向项目根
--force --persist 时若已有 MASTER.md，默认跳过；加此旗标才覆盖
--domain -d 只搜某一个知识域（与 --design-system 二选一使用场景）
--stack -s 只搜某一技术栈的实现指南
--max-results -n 单域 / 单栈最多返回几条，范围 1–20，默认 3
--json 输出 JSON，方便脚本处理
--full 文本模式下不截断过长字段
--variance 仅设计系统：版式大胆程度 1–10（1 偏居中极简，10 偏不对称大胆）
--motion 仅设计系统：动效强度 1–10，并会拉匹配的 GSAP 片段
--density 仅设计系统：视觉密度 1–10（1 偏疏，10 偏仪表盘式紧凑）

生成设计系统

功能：根据 query 推断产品与氛围，输出可直接约束实现的完整设计系统到终端（不落盘，除非再加 --persist）。

第一条里各段在做什么：python3 …/search.py 启动检索；"beauty spa wellness" 是匹配用的行业关键词；--design-system 打开多域推理；-p "Serenity Spa" 只影响输出里展示的项目名（以及配合 --persist 时的目录 slug）。

示例：完整 ASCII 输出在说什么

下面是本机对第一条命令跑出来的摘要（框线与字段名以 2.15.x 为准；色值等会随版本与推理结果变化）。OpenCode 全局安装时路径可能是 ~/.opencode/skills/ui-ux-pro-max/scripts/search.py，读法相同。

本例色板对照：

角色 色值 建议变量 用途直觉
Primary / On Primary #EC4899 / #000000 --color-primary / --color-on-primary 主色与其上文字、图标
Secondary / On Secondary #F9A8D4 / #0F172A --color-secondary / --color-on-secondary 次要强调
Accent/CTA / On Accent #8B5CF6 / #000000 --color-accent / --color-on-accent 行动按钮（偏紫）

各块怎么用：

  • TARGET — 本次推荐服务的项目名，来自 -p。

  • PATTERN — 页面信息架构与转化路径。本例是 Hero → 社会认同（评价轮播）→ CTA；Conversion 里还约束了轮播：要有上一项 / 下一项 / 暂停，焦点、悬停、prefers-reduced-motion 时停转，播报当前片位置，键盘能翻完所有页（不能只靠拖拽）。写落地页按 Sections 顺序排区块；CTA 放在 Hero（可 sticky）和评价区之后。

  • STYLE — 视觉手感。本例 Soft UI Evolution：柔和纵深、对比度优先，适合养生 / 健康 / 偏专业的产品。Performance / Accessibility 行是实现底线（对比度 ≥ 4.5:1、键盘、可见焦点、减少动效）。库可能标 Light/Dark 都支持；若 AVOID 写了 Dark mode，本产品默认仍走浅色更稳，深色要单独验对比度。

  • COLORS — 语义色板：角色 + hex + CSS 变量名。实现时建成 token，组件引用变量，避免散落写死 hex。Notes（Soft pink + lavender luxury）概括气质。

  • TYPOGRAPHY — 标题 / 正文字体配对。本例 Lora + Raleway，偏冷静、养生；完整输出里的 Google Fonts 链接与 @import 可直接用于项目。

  • KEY EFFECTS — 阴影比扁平略软、又比新拟态更清晰；过渡约 200–300ms；焦点必须看得见；按对比度目标落地。

  • AVOID — 反模式：霓虹亮色、生硬动画、默认冲深色主题；与粉紫浅底色板一致。

  • PRE-DELIVERY CHECKLIST — 交付前核对：SVG 图标（Heroicons/Lucide）、cursor-pointer、悬停 150–300ms、浅色对比度、焦点环、prefers-reduced-motion、375 / 768 / 1024 / 1440 断点。Agent 声称做完前应按项自检。

整份输出是后续写 Hero、评价区、按钮和全局 CSS 的硬约束。需要跨会话复用时，同一命令加 --persist 落盘即可（见下一节）。

持久化（Master + 页面覆盖）

功能：在 --design-system 之外把结果写成文件，供后续会话按「全局规范 + 单页覆盖」读取。2.15.x 默认写到 design-system/<项目名 slug>/ 下。

目录形态（示意）：

之后做某页时，先读 MASTER.md；若存在 pages/<页>.md，以页面文件为准覆盖 Master。可在对话里明确要求 Agent 按这个层级取规则。

按域补充

功能：不走完整设计系统，只在某一个域里搜几条明细。适合已有大方向、还缺风格备选、字体、图表或 UX 细则时。

常用 --domain：以本机 search.py --help 为准

Domain 搜什么
product 产品类型与推荐模式
style UI 风格、视觉效果关键词
typography 标题/正文字体配对
color 按产品类型的配色角色
landing 落地页结构、CTA 策略
chart 图表类型与用法
ux UX 最佳实践与反模式
icons 图标相关建议
gsap 动效 / GSAP 片段类条目
google-fonts 单个 Google Font 查询
react React / Next 性能类条目
web 应用界面（触控、安全区等）

按技术栈

功能：在某一框架的指南库里搜实现向条目（组件、布局、校验等），与 --domain 同属「单库检索」，只是数据源换成 stacks/*.csv。

2.15.0 可用的 --stack 如下（数据来自 CLI 包内 stacks/*.csv；以本机 search.py --help 为准）。选与项目实现最接近的一项；搜词写该栈里的主题（如 form validation、navigation）。

怎么选调用方式

你想做的事 怎么调
新项目 / 新站先定视觉规范 --design-system，必要时加 -p、-f markdown
规范要跨会话复用 同上并加 --persist；单页差异再加 --page
已有规范，只补某类细节 --domain …
只要某框架落地注意点 --stack …
给脚本读 加 --json

先有设计系统再铺页面。只凭自然语言让 Agent「随便做个好看的站」，会跳过本技能的推理层，配色与反模式容易漂。已 --persist 的项目，改视觉规范应先改 design-system/，再改组件。

用 Capacitor 把 Vue 项目打成 Android / iOS 应用

  4. 用 Capacitor 把 Vue 项目打成 Android / iOS 应用

摘要

  • 本文写 Capacitor：把已有 Vue（Vite）Web 工程包进原生壳，生成可在 Android Studio / Xcode 中打开的原生工程，并说明安装、日常同步、调试与常用 CLI 参数。
  • 操作环境按 macOS，Capacitor 按 @capacitor/core / @capacitor/cli 8.6.3，需要 Node.js ≥ 22。Web 侧以 Vue 3 + Vite 为例，webDir 为 dist。Android 需 Android Studio；iOS 需本机 Xcode（仅 macOS）。
  • 官方文档：Using Capacitor with Vue、Installing Capacitor、Environment Setup、Development Workflow、CLI Reference、Configuration。同系列见 用 create-vue 创建 Vue 3 项目。

它解决什么问题

Capacitor 在 Web 应用外包一层原生容器：界面仍是你的 Vue 页面（跑在系统 WebView 里），同时通过插件调用相机、文件系统、推送等原生能力。相对 Cordova，它把 android/、ios/ 当成可提交到 Git 的一等工程，改原生代码、用官方 IDE 打包都更直接。

典型流程：npm run build 产出静态资源 → npx cap sync 拷进原生工程并更新原生依赖 → 用 Android Studio / Xcode（或 cap run）安装到模拟器或真机。

它不会把 Vue 编译成 Kotlin / Swift；改的是 Web 构建结果和原生壳配置。路由请用 Hash 或正确配置 History（注意 Android 自定义 scheme 与 WebView 限制，见下文 server）。

前置环境

目标 需要
通用 Node.js 22+（本文按 CLI 8.x）
Android Android Studio（Capacitor 8 要求 2025.2.1 起）、SDK Platform API 24+（日常可装较新稳定版）
iOS macOS、Xcode（Capacitor 8 要求 Xcode 26.0 起）、Command Line Tools

Android 不必单独装 JDK，Android Studio 会带合适 JDK。iOS 默认用 Swift Package Manager；只有仍依赖 CocoaPods 的插件时，才在 cap add ios 时选 CocoaPods，并自行准备 pod。

确认基础工具：

App Store 上的 Xcode 往往只提供当前最新版。若本机是 Intel Mac，新版 Xcode 可能已要求 Apple Silicon，商店里会搜不到或无法安装；需从 Apple Developer Downloads 下载仍支持本机的 Universal / 旧版 Xcode。长期上架 iOS 仍建议准备 Apple silicon 机器。

找不到 Android Studio 时，可设环境变量 CAPACITOR_ANDROID_STUDIO_PATH 指向可执行文件；CocoaPods 路径可用 CAPACITOR_COCOAPODS_PATH。

安装到已有 Vue（Vite）项目

项目需具备：package.json、构建产物目录（Vite 默认 dist）、产物根上有带 <head> 的 index.html（否则插件注入会失败）。新建 Vue 工程见 用 create-vue 创建 Vue 3 项目。

在项目根执行：

cap init 参数：

参数 含义
appName 应用显示名（商店里看到的名字可再在原生工程里改）
appID 应用 ID，反向域名，如 com.example.myapp；对应 Android applicationId、iOS Bundle ID。上架后不宜随意改
--web-dir <dir> Web 构建输出目录。Vite 默认 dist；若改过 build.outDir，这里必须一致

也可只跑 npx cap init 走交互问答。生成后检查配置里的 webDir，同步时报找不到 web assets 多半是这里错了。

安装并添加原生平台：

cap add 参数：

参数 含义
platform 必填：android 或 ios
--packagemanager 仅 iOS：SPM（默认）或 Cocoapods

会在仓库根生成 android/、ios/。官方建议把它们纳入版本管理，当作应用的一部分。

首次把 Web 与原生依赖对齐：

确认：存在 capacitor.config.ts（或 .json）、android/、ios/；android/app/src/main/assets/public（或等价目录）里能看到构建后的前端文件。

配置文件要点

capacitor.config.ts 示例（Vite）：

常用顶层字段：

字段 作用
appId 包名 / Bundle ID
appName 应用名
webDir 同步用的 Web 产物目录
loggingBehavior 日志：none / debug（默认）/ production
backgroundColor WebView 背景色
zoomEnabled 是否允许双指缩放，默认 false
initialFocus WebView 是否初始获焦，默认 true
includePlugins sync 时只纳入列出的插件包名；不设则按 package.json 探测
server.url WebView 加载的地址。开发期常指本机 / 局域网，做 live reload；也可指正式 https:// 做「壳 + 远程 H5」
server.cleartext Android 允许明文 HTTP；只适合本地联调，上架包不要开
server.hostname 本地主机名，默认 localhost
android.path / ios.path 原生工程目录，默认 android / ios
android.allowMixedContent 允许混合内容，仅建议开发期
ios.scheme iOS 构建 scheme，默认 App

官方文档把 server.url 标成开发向（live reload），是因为默认发布模型是：把 webDir 打进包内再离线打开。大厂常见的「原生壳 + 远程 H5」也可以用正式 https:// 域名做同类事，但那是远程页面架构：上架配置里不要留开发机 IP、明文 HTTP 或未加固的临时地址；并自行处理断网降级、资源校验和商店审核（iOS 对偏薄的套壳更严）。cleartext / 局域网 live reload 只留在调试包。

改配置后需要再执行 copy 或 sync，原生工程里的配置副本才会更新。完整字段见 Configuration。

日常开发流程

开发期可用 live reload（电脑与手机同一局域网）：

生产包更常见的是在 Android Studio / Xcode 里 Archive / Generate Signed Bundle；也可用 npx cap build（见下）。

卸载平台：删掉对应 android/ 或 ios/ 目录，并从 package.json 去掉 @capacitor/android / @capacitor/ios（若不再需要）。重新 cap add 会再生成一份原生工程，此前在原生侧的手工修改会丢，先备份。

CLI 命令与参数

全局形式：

命令 作用
init 生成 Capacitor 配置
add 添加 android / ios 原生工程
sync 先 copy 再 update
copy 只把 Web 产物和配置拷进原生工程
update 只更新原生侧插件与依赖
open 用 Android Studio / Xcode 打开工程
run sync（可关）后构建并部署到目标设备
build 产出签名 AAB / APK / IPA
ls 列出已安装的 Capacitor 插件
doctor 检查环境 / 依赖问题（含 npm 拦截 install script 等）
migrate 辅助升级 Capacitor 大版本（以当前 CLI 帮助为准）

sync

参数 含义
platform 可选：android、ios；省略则两边都做
--deployment iOS：保留 Podfile.lock，pod install 带 --deployment
--inline 内联 JS source map，便于用 Chromium 调试 Android WebView

钩子：capacitor:sync:before / capacitor:sync:after。

copy / update

命令 何时用
copy 只改了 Web 或配置，原生插件依赖没变
update 装/升级了 Capacitor 插件，需要刷新原生依赖
sync 日常默认；等价于两者都做

copy 也支持 --inline。update 支持 --deployment（同 sync）。

open

platform 必填：android 或 ios。

run

参数 含义
platform 必填：android、ios
--list 列出该平台可用设备
--target <id> 指定设备 ID
--target-name <name> 按设备名，如 "iPhone 17 Pro"
--target-name-sdk-version <ver> 与 --target-name 联用，区分同名不同系统版本的设备
--no-sync 跳过同步（你刚 sync 过时可省时间）
--flavor <name> Android product flavor
--scheme <name> iOS scheme
--configuration <name> iOS scheme 的 configuration
-l / --live-reload 启用 live reload（覆盖配置里的 server.url）
--host / --port / --https 配合 live reload 的主机、端口、是否 https
--forwardPorts <ports> Android：自动 adb reverse，改善 live reload

build

参数 含义
platform 必填：android、ios
--flavor Android flavor
--androidreleasetype AAB 或 APK
--keystorepath / --keystorepass 密钥库路径与密码
--keystorealias / --keystorealiaspass 别名与别名密码
--signing-type jarsigner（默认）或 apksigner
--scheme / --configuration iOS scheme 与 configuration
--xcode-team-id Apple Developer Team
--xcode-export-method 导出方式，默认 app-store-connect；另有 release-testing、debugging 等
--xcode-signing-style automatic（默认）或 manual
--xcode-signing-certificate 证书名 / SHA-1 / 自动选择器
--xcode-provisioning-profile 描述文件名或 UUID

签名信息也可写在 capacitor.config 的 android.buildOptions / ios.buildOptions，避免每次把密码写在命令行历史里。

排错要点

  • 找不到 web assets 目录：核对 webDir 与 Vite outDir，并先 npm run build。

  • 真机界面不更新：漏了 build + sync（或 copy）。

  • npx cap doctor：检查 Node、平台工具、以及 npm 12 拦截依赖 install script 等情况；若脚本被拦，按提示 npm install-scripts approve 后再 npm rebuild。

  • iOS 仅能在 Mac 上本地编：无 Mac 时只能靠云构建，日常调试仍建议本机 Xcode。

相关工具对照

和 Capacitor 同属「Web / 跨端到安装包」一类的常见选择。推荐指数按 Vue 3 场景打分（满分 ★★★★★）：侧重能否保住 Vue 3 / Vite 技术栈、承接现有 SPA、以及出 App / 多端时的常见匹配度；不是跨技术栈的绝对排名。

工具 Vue 3 推荐 特点
Capacitor ★★★★★ 标准 Vue 工程加原生壳；dist sync 进 Android / iOS，改动面小，本文主路径
Quasar ★★★★★ Vue 全家桶式框架，可同时出 SPA / PWA / Capacitor / Cordova / Electron；统一组件，多模式切换
Ionic ★★★★☆ 提供 Ionic Vue 与移动风 UI；底层常用 Capacitor 出 App；适合从零做移动 H5 再进壳
uni-app ★★★★☆ Vue 语法 + 自有组件 / API；一套代码出 App、各家小程序、H5；国内物料全，承接标准 Vue Web 成本较高
PWA ★★★★☆ 仍是浏览器里的 Vue 站点；可「添加到主屏幕」、推送等。无独立商店壳，能力受浏览器限制
Electron ★★★★☆ 用 Chromium 包 桌面；Vue 3 可直接做渲染进程。目标端是桌面不是手机，包体积大
Tauri ★★★★☆ 桌面壳 + 前端 Web（可用 Vue 3）；安装包通常比 Electron 小。移动端成熟度不如桌面
Taro ★★★☆☆ 支持 Vue 3，但生态与文档仍偏 React / 小程序；App 主路径弱于 uni / Capacitor
Apache Cordova ★★☆☆☆ 更早的 WebView 壳；插件多但老。新 Vue 3 项目更宜直接 Capacitor
React Native ★★☆☆☆ 原生控件、体验更好，但不是 Vue；不能原样打包现有 Vue 3 站点
Flutter ★☆☆☆☆ Dart + 自绘 UI；与 Vue 3 技术栈独立，迁移等于重写界面

已有 Vue 3 Web、只要 iOS / Android 商店包：优先 Capacitor（或 Quasar / Ionic 的 Capacitor 模式）。必须覆盖微信等小程序：看 uni-app / Taro。只要桌面：Electron / Tauri。要原生控件级体验且可接受换栈：React Native / Flutter。

和 uni-app 怎么选

两者都能做出 Android / iOS 安装包，路径差很多。

Capacitor uni-app
定位 给已有 Web / Vue 工程加原生壳 用自有 DSL + Vue 语法重写/新建多端应用
页面与生态 标准 Vue / Vite、npm 组件、大部分 Web 库可继续用 组件与 API 走 uni 规范；条件编译打多端
目标端 主要是 WebView 壳上的 iOS / Android（也可继续当 PWA） 同一套代码可出 App、各家小程序、H5 等
原生工程 生成可提交的 android/、ios/，用 Android Studio / Xcode 深度改 发行多走 HBuilderX / 云打包；本地离线打包另有流程
适合 已有 Vue 网站或 SPA，要「包一层」上架；要直接改原生工程 从零做多端（尤其小程序 + App），接受 uni 组件与 API

Capacitor 相对 uni-app 的优点

方面 说明
承接现有 Vue 标准 Vue Router、Pinia、npm 组件和多数 Web 库可继续用，不必换成 view / uni.xxx 那一套
Web 与 App 同源 同一套 Vite 构建既能当网站 / PWA，也能 sync 进壳；联调路径接近普通前端
原生工程透明 android/、ios/ 可进 Git，用 Android Studio / Xcode 改权限、推送、签名、自定义原生模块更直接
插件与社区 偏「Web + 原生桥」国际生态；官方与 npm 社区插件按 Web API 风格调用，和 Cordova 插件也有一定兼容路径
工具链 不绑特定国内 IDE / 云打包；日常 build → sync → 官方 IDE 即可，CI 也可走 cap build

Capacitor 相对 uni-app 的局限

方面 说明
小程序 不出微信 / 支付宝 / 抖音等；主战场是 App（加 Web），小程序要另做或换 uni
渲染模型 UI 仍是 WebView；复杂列表、大量原生手势、极致性能不如纯原生，也不如 uni 部分端上的原生渲染优化；重交互要自己找插件或写原生
多端覆盖 「一套代码全包」不如 uni；uni 用条件编译同时照顾小程序 + App + H5，Capacitor 没有对等的小程序编译管线
国内物料 登录、支付、分享、厂商推送等，uni 生态和文档更贴国内应用商店习惯；Capacitor 往往要自接 SDK 或找社区插件
发行与审核 商店合规、隐私清单、套壳审核风险都落在原生工程上；没有 uni 云打包那套一站式发行体验

已有一套 Vue 3 + Vite 业务、只想上架 App、并保留现有路由与 npm 依赖时，Capacitor 改动面更小：装 CLI、设 webDir、sync 即可。若还要微信 / 支付宝等小程序，且愿意按 uni 规范写页面，选 uni-app 更合适；强行把现有 Web 工程「迁成 uni」往往等于重做 UI 层。

两者也可以分工：H5 / 开放 Web 用 Vue + Capacitor；小程序线单独用 uni。不必绑死一个工具覆盖所有端。

Vue 3 全量引入与按需导入

摘要

  • 说明 Element Plus、@element-plus/icons-vue、ECharts 的全量引入与按需导入差在哪里、适合什么场景，以及按需时要装哪些插件、怎么改 Vite 与入口代码
  • 本文按 Vue 3 + Vite。示例对应 Element Plus 2.x、ECharts 5+ / 6.x、unplugin-vue-components@32.x、unplugin-auto-import@21.x
  • 官方文档：Element Plus 快速开始、Element Plus 国际化、ECharts 按需引入。脚手架创建见 用 create-vue 创建 Vue 3 项目

两种引入方式差在哪

全量引入 按需导入
做法 入口一次 app.use(ElementPlus)，或 import * as echarts from 'echarts' 构建期只打进用到的组件 / 图表 / 样式
首包体积 大，未用到的也会进包 通常更小
写法成本 低，模板里直接用 要配插件，或手写 import / echarts.use
维护点 少 动态组件名、漏注册图表时要补；改造后要对比 dist 体积
典型场景 内网后台、功能面广、优先稳定 公网首屏、包体积已成为明确瓶颈

按需导入不会换成别的 npm 包。element-plus、@element-plus/icons-vue、echarts 仍留在 dependencies 里；改的是从这些包里拆出用到的模块。需要新增的是开发依赖（如 unplugin-vue-components、unplugin-auto-import）。需要删掉的是代码里的全量用法，不是 npm uninstall 这些库。

配了按需插件之后，入口里若仍保留 app.use(ElementPlus) 和 import 'element-plus/dist/index.css'，构建仍会把整库打进去，体积与全量无异。两种写法不要叠在一起。

什么时候用全量，什么时候按需

适合继续全量：

  • 内网管理系统，带宽和首屏不是痛点

  • 页面大量使用组件库，按需省下的体积有限

  • 侧边栏等用字符串动态渲染图标（meta.icon），全量全局注册更省事

  • 团队优先少配置、少踩「漏注册」类问题

适合改成按需：

  • 公网或移动端，要压首包、改善首屏

  • npm run build 后产物体积已成明确瓶颈

  • 实际只用到少量组件或少数图表类型

改造后务必对比 dist/ 体积并过一遍关键页面。下降不明显就回退，避免白增加维护成本。

类型可继续用宽松的 EChartsOption，或按官方方式用 ComposeOption 收窄为本项目用到的组合。仅 import type 的类型导入不进运行时包。

注意点

  • option 里用了未 use 的系列或组件时，图表空白或控制台报错，需对照页面补全

  • 改前先扫一遍项目里实际用到的图表类型和组件，再定 use 列表

改造检查清单

若从全量改到按需，按下面顺序做：

  1. 安装并配置 unplugin-vue-components、unplugin-auto-import；保留 element-plus / icons / echarts 依赖

  2. 去掉入口中 Element Plus 全量 use 与全量 CSS（不要 uninstall 包）

  3. 根组件用 el-config-provider 设语言，并引入 dayjs/locale/zh-cn

  4. 决定图标策略：显式导入、白名单注册，或暂时全量保留

  5. 图表封装改为 echarts/core + 按需 use

  6. 跑类型检查与 npm run build，本地过一遍主要页面

  7. 对比改造前后 dist/ 体积；下降不明显可回退

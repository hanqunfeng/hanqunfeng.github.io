摘要

  • 本文写 Versions Maven Plugin：在项目根执行几条命令，列出依赖、插件、<properties> 里声明的版本是否有新版，作用接近 npm outdated。
  • 操作环境按 macOS，插件按 versions-maven-plugin 2.25.3。一般不必改 pom.xml，直接 mvn versions:… 即可；会改 pom 的自动升级命令单独说明。
  • 官方文档：Introduction、Usage、display-dependency-updates、display-property-updates。同系列见 发布Jar到Maven中央仓库--Maven版(最新方式)。

它解决什么问题

想知道当前工程里哪些依赖、插件还能升版本时，不必逐个打开 Maven Central 对照。Versions Plugin 扫项目的依赖声明和版本属性，在终端打出「当前版 → 可用新版」一类报告。只查、不改 pom 时，用 display-* 这组 goal 即可。

日常推荐：只查自己声明的版本

日常习惯是：只关心本工程显式声明、或写在 <properties> 里的版本。由 Spring Boot BOM（或其它 BOM / dependencyManagement）管住的传递坐标，一般跟着升 BOM / Boot 即可，不必逐个对表。

在项目根（有 pom.xml 的目录）执行；多模块建议在聚合根上跑。下面命令都只读报告，不改 pom.xml。

对依赖这条，插件默认会扫 <dependencies>、<dependencyManagement>（含 import 的 BOM）、以及插件 / pluginManagement 里用到的依赖；且 processDependencyManagementTransitive 默认为 true，会把 BOM 展开，对其中每个坐标都去仓库问有没有新版（多半拉 maven-metadata.xml）。Spring Boot 一类 BOM 往往有几百条，于是：

  • 跑很久，日志里像一直在下载

  • 刷出大量「没写在本模块 <dependencies> 里」的更新，噪音大，也不适合当作日常待办

这和 mvn dependency:tree 里的运行时传递依赖（A→B→C 的 C）不是同一套逻辑；参数名里的 transitive 指的是 BOM / dependencyManagement 的展开。说明见 display-dependency-updates、Reporting imported BOMs。

另外，默认的 display-dependency-updates 还会检查 插件依赖（processPluginDependencies、processPluginDependenciesInPluginManagement 默认为 true），坐标再多一轮，时间更容易被拖长。日常用上一节的收窄参数即可关掉 pluginManagement 里那一块。

display-plugin-updates 本身通常不会像依赖那条一样展开整个 BOM，但默认仍可能带上 pluginManagement 里的条目；需要「只看本模块声明并使用的插件」时，加上面的 -DprocessPluginManagement=false。

可选：自动改 pom 升版本

下面两条会改写 pom.xml。先提交或备份，升完再编译、跑测试；大版本跳跃可能带破坏性变更。

-N、-pl 是 Maven 的 reactor 开关，对 update-properties 同样生效。版本集中在根 pom 时用 -N，只改根、不进子模块；某个子模块自己有版本属性时用 mvn -pl :模块artifactId versions:update-properties。

版本主要靠属性管理时，优先 update-properties，和日常维护方式一致。改完用 git diff 核对变更范围，再跑构建。

和其他工具怎么分工

工具 用途
Versions Maven Plugin 本地查 / 升版本，最接近 npm outdated
Dependabot / Renovate 在 CI 里开升级 PR，适合持续跟进
OWASP Dependency-Check 查已知安全漏洞，不专门列「有没有更新的版本」

先用收窄后的 display-* 摸清可升级项，再决定手改、跑 update-properties，还是交给 Dependabot / Renovate 出 PR。

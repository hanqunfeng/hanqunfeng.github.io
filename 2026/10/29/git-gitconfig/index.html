摘要

  • 本文写当前用户的 Git 配置文件 ~/.gitconfig：它为什么存在、和仓库里的 .git/config 谁生效、怎么创建和修改、常用项，以及怎么核对实际读到的值。本文按 Git 2.56.0。
  • HTTPS 凭据助手见 Git 的 HTTPS 凭据和 SSH 密钥。按目录换邮箱见 同一台电脑使用两个 GitHub 账号。签名密钥写在这个文件里，见 用 SSH 密钥签名 Git 提交。
  • git-config。

为什么有这个文件

姓名、邮箱、编辑器、拉取方式这些选项，每个仓库都可以单独放一份。放在 ~/.gitconfig 里之后，这个用户新建或克隆的仓库都会带上，不用每个目录再设一遍。

文件在用户主目录，不在仓库里，git clone 不会把它带走，也不会提交进历史。改它只影响这台机器上、这个用户以后执行的 Git 命令。已经生成的提交不会因此改写。

几份配置谁生效

Git 每次执行都会重新读配置文件，没有单独的进程需要重载。后读到的同名键覆盖先读到的。

范围 写入选项 文件 管哪些仓库
system --system $(prefix)/etc/gitconfig 这台机器上的所有用户
global --global ~/.config/git/config，然后是 ~/.gitconfig 当前用户的所有仓库
local 在仓库里执行，不加范围 .git/config 只这个仓库
单次 git -c 键=值 不写文件 只这一条命令

$XDG_CONFIG_HOME 有值时，用它代替 ~/.config。两份全局文件都存在时都会读，~/.gitconfig 里的同名键盖过 ~/.config/git/config。仓库里的 .git/config 再盖过全局。

--global 默认写 ~/.gitconfig。只有 ~/.gitconfig 还不存在、并且 ~/.config/git/config 已经存在时，才会改写后者。

git -c user.email=临时@example.com commit 只影响这一次，文件内容不动。环境变量 GIT_AUTHOR_EMAIL、GIT_COMMITTER_EMAIL 也只影响当前这次提交的作者或提交者，不写入 ~/.gitconfig。

创建和修改

还没有这个文件时，第一条 --global 会创建它。

用编辑器打开同一份文件。保存后，下一条 git 命令就会读到新内容。

也可以直接编辑 ~/.gitconfig。它是隐藏文件，ls -a ~ 才能看见。语法和 .git/config 相同：方括号是节，节里面是键和值。# 开头的是注释。

只想改当前这个仓库时，在仓库目录里执行，不加 --global。值写入该仓库的 .git/config，并盖过 ~/.gitconfig 里的同名键。

同一个键在文件里出现了多行时，普通的设置命令会报错。--replace-all 把这些行全部换成新值。

常用项

键 作用
user.name 以后新提交的作者名
user.email 以后新提交的作者邮箱。GitHub 用它对应账号
core.editor git commit、git rebase -i 打开的编辑器
init.defaultBranch git init 时的默认分支名。设为 main 后，新仓库的第一分支叫 main
pull.rebase true 时，git pull 用变基接上远程分支，不再产生合并提交
push.autoSetupRemote true 时，新分支第一次 git push 会自动建立上游跟踪，不用再写 -u。Git 2.37 起可用
core.excludesfile 所有仓库共用的忽略文件，见 Git安装和常用命令(最新) 的「.gitignore」一节
credential.helper HTTPS 密码交给哪个助手。助手的配置见 Git 的 HTTPS 凭据和 SSH 密钥

pull.rebase true 写进 ~/.gitconfig 之后，这个用户的每个仓库，以后的 git pull 都改走变基。已经存在的合并提交不会被改写。

密码和令牌不要写进这个文件。credential.helper 只记录用哪一个助手，口令在钥匙串或助手自己的存储里。

签名用的 gpg.format、user.signingkey、commit.gpgsign 也放在这里，步骤见 用 SSH 密钥签名 Git 提交。

MacPorts -- 创建自己的 Port

发表于 2026-10-16 更新于 2026-10-19 分类于 macos 置顶 精品
阅读次数： 0 本文字数： 4.1k 阅读时长 ≈ 15 分钟

摘要

  • Portfile 是 MacPorts 的安装脚本，对应 Homebrew 的 formula。官方 ports 树里没有的软件，可以放在本机的一个目录里，在 sources.conf 登记之后，用同样的 port install 安装。
  • 本地目录要写成 file://，放在带 [default] 的那一行前面，并加上 [nosync]。Portfile 放在 分类/名字/Portfile。改完在仓库根目录执行 portindex。
  • 下面用 brew -- 创建自己的 Formula 里的 color_echo 1.0.0 作例子。源码是 GitHub tag v1.0.0 的归档，命令文件在 bin/color_echo。安装和日常命令见 MacOS软件包管理器--MacPorts。没有 brew tap 这种命令，个人仓库是一份 Git 上的 ports 树，别人克隆后写进自己的 sources.conf。
  • 本机 MacPorts 是 2.12.7。sources.conf 里的默认行是 ports.tar.gz，不是指南旧示例里的 ports.tar。

Portfile

  • 文件是 Tcl。第一行是编辑器模式标记，后面先声明 PortSystem，GitHub 上的项目再加 github 1.0。字段说明见 Portfile Reference，GitHub 这一组见 PortGroups 里的 github。

  • github.setup 的四个参数是作者、仓库、版本、tag 前缀。1.0.0 配 v，tag 就是 v1.0.0。github.tarball_from 默认是 releases，读的是 Releases 页面上挂的附件。color_echo 用的是 tag 归档，要改成 archive，地址才是 https://github.com/hanqunfeng/color_echo/archive/refs/tags/v1.0.0.tar.gz。

  • 这份归档解压后的目录是 color_echo-1.0.0。archive 会打开 extract.rename，工作目录和这个名字对齐。脚本在 bin/color_echo，没有编译步骤。

  • 创建 ~/ports/sysutils/color_echo/Portfile 文件：

  • 各字段含义如下：

    • 第一行：给编辑器看的模式行，标明这是 Tcl / Portfile，缩进 4 空格；MacPorts 本身不解析它。
    • PortSystem 1.0：启用 Portfile 基础设施，每个 Portfile 都要写。
    • PortGroup github 1.0：引入 GitHub 相关辅助命令，后面才能用 github.setup、github.tarball_from。
    • github.setup：四个参数依次是 GitHub 作者、仓库名、版本号、tag 前缀。这里是 hanqunfeng / color_echo / 1.0.0 / v，对应 tag v1.0.0。
    • github.tarball_from archive：从 tag 归档下载；默认 releases 会去 Releases 附件，对不上时要改成 archive。
    • revision：同一上游版本下 Portfile 自己的修订号。只改安装步骤时加 1；换了上游版本则改 github.setup 里的版本，并把 revision 回到 0。
    • categories：软件分类，第一项应和本地目录名一致，这里是 sysutils。
    • platforms any：不限运行平台；纯脚本常见写法。
    • supported_archs noarch：没有按 CPU 架构区分的二进制，arm64 / x86_64 共用同一份。
    • license：上游许可证，这里是 MIT。
    • maintainers：维护者；只在本机用可写 nomaintainer。
    • description：一句话短描述，出现在 port search、port info。
    • long_description：长描述。{*}${description} 表示直接展开复用短描述。
    • checksums：校验下载到的压缩包。rmd160、sha256 是摘要，size 是字节数；三个都针对 .tar.gz 本身。
    • use_configure no：跳过 ./configure。
    • build {}：空的编译阶段，表示没有编译步骤。
    • destroot { ... }：安装阶段。${worksrcpath} 是解压后的源码目录，xinstall 把 bin/color_echo 复制成可执行文件。复制目标是 ${destroot}${prefix}/bin/color_echo，两个变量的含义见下面。

  • sha256 与 brew -- 创建自己的 Formula 里同一份 v1.0.0.tar.gz 一致。rmd160 和 size 先占位，下一步用本机算出来的值换掉。只给自己用时，maintainers 写 nomaintainer 即可。

  • ${prefix} 是装好之后的前缀。本机是 /opt/local，所以这条命令最后出现在 /opt/local/bin/color_echo。

  • ${destroot} 是这一次安装的临时目录，在 /opt/local/var/macports/build/ 下面、这个 port 的 work/destroot。它当时还是空的，里面会按前缀再套一层目录。

  • 两个变量连着写，${destroot}${prefix} 就是「临时目录 + /opt/local」。这条 xinstall 的目标是：

  • MacPorts 先在这个临时目录里装完，记下相对 ${destroot} 的路径，再把 destroot/opt/local/ 下面的内容移到真正的 /opt/local。卸载时按这份记录删除。文件在 destroot 阶段就直接写进 /opt/local/bin，登记里没有它，以后 port uninstall 不会把它删掉。

个人仓库

  • MacPorts 没有 brew tap user/repo。能分发给别人的，是一个目录结构和本机 ~/ports 相同的 Git 仓库：分类/名字/Portfile。别人克隆下来，在自己的 sources.conf 里加一行 file://，就能 port install。说明见 sources.conf。

  • 把已经写好的 ~/ports 推上去即可。PortIndex 由使用者本机生成，不必提交：

  • 使用者克隆后做一次索引，再把绝对路径写到带 [default] 的那一行前面：

  • [nosync] 时，selfupdate 不会碰这个目录。仓库有更新时，自己 git pull，再在仓库根目录执行 portindex。

  • 去掉 [nosync] 后，selfupdate 发现这是 Git 检出，会向默认远程 pull，并重建索引。执行同步的是 macports 用户，这个目录要让它可写。家目录通常不行，检出放到它能写的路径，例如 /opt/local/var/macports/sources/github.com/hanqunfeng/my-ports。

提交到官方仓库

  • 个人仓库要别人改自己的 sources.conf 才能用。希望不改配置、一条 port install color_echo 就能装到，把 Portfile 交给 macports-ports。步骤就是 fork、单独一个分支、一条提交、开 pull request。耗时间的是这个仓库本身很大，以及 GitHub Actions 编译和别人审 Portfile。Portfile 写法见 Creating a Portfile，提交说明见 CommitMessages 和 Using Git and GitHub。

  • 提交前在本机走通 port lint --nitpick color_echo 和 sudo port install color_echo。准备自己维护这个 port，把 maintainers nomaintainer 改成 maintainers {@hanqunfeng}。留给别人维护就保持 nomaintainer。

  • 官方仓库是 macports/macports-ports。没有推送权限，直接克隆官方地址后，git push 会被拒绝。先在 GitHub 上点 Fork，得到自己的 hanqunfeng/macports-ports，再克隆这一份。只克隆一层历史，避免把整个 ports 树的历史都拉下来：

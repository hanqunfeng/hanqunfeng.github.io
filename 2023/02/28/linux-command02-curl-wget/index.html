curl 和 wget 怎么选

curl 默认把响应打到标准输出，适合看接口、接管道、写脚本。wget 默认按 URL 里的文件名存到磁盘，适合下载文件和递归镜像。

curl wget
默认行为 响应打到标准输出 保存为文件
整站抓取 不做网站镜像 --mirror / -r 递归下载
请求构造 方法、Header、JSON、上传都直接支持 以 GET 下载为主，也能 POST、加 Header
失败与重试 --retry、-f、-w 适合写进脚本 -c 断点续传、-t 重试次数
常见环境 Linux、macOS 大多自带 Linux 大多自带，macOS 通常要另装

CentOS Linux 8 已于 2021-12-31 停止维护，默认的 yum 源已经迁入归档。还在用这套系统时，可以临时把系统源换成 https://vault.centos.org 后再执行文中的 yum。

Vault 只是冻结的历史软件包归档，不再提供安全更新，不能视为恢复了系统维护。生产环境应尽快迁移到仍受支持的 Rocky Linux、AlmaLinux、RHEL 或其他系统。EPEL 8 本身仍跟随 RHEL 8 生命周期维护到 2029-05-31，但它依赖的 CentOS Linux 8 基础仓库仍可能因为系统停止维护而安装失败。

curl

版本提示

本文以 CentOS 8 自带的 curl 7.61.1 为基础，不同版本的常见差异如下：

  • 7.66.0：增加 --parallel 并行传输

  • 7.67.0：HTTP 429 开始触发 --retry

  • 7.73.0：增加 --output-dir，curl --help 改为只显示常用参数，完整参数使用 curl --help all

  • 7.76.0：增加 --fail-with-body

  • 7.82.0：增加 --json

  • 8.2.0：增加 --ca-native、--proxy-ca-native，可以使用操作系统原生 CA 存储

  • 8.3.0：增加命令行变量 --variable 和 --expand-*

  • 8.10.0：增加 --skip-existing，并支持用 curl --help 参数名 查看指定参数的帮助

  • 8.13.0：--url @文件 可以从文件读取 URL 列表

  • 8.16.0：增加 --follow、--out-null、--parallel-max-host，重试时间支持小数，并把默认最低 TLS 版本提升到 1.2

  • 8.19.0：--limit-rate、--max-filesize 支持小数

  • 8.20.0：上游构建默认关闭 NTLM，SMB 改成编译时选择启用，并移除 RTMP

  • 8.21.0：URL glob 支持命名，并增加 HTTP/3 代理 CONNECT、MASQUE CONNECT-UDP

  • 8.22.0：增加实验性的 RFC 9421 HTTP Message Signatures；移除 TLS-SRP，并阻止 SPNEGO 自动回退到 NTLM

截至 2026-09-02，curl 最新稳定版是 8.22.0。先用 curl --version 查看实际版本和编译特性，再决定是否使用较新的参数；发行版自带的 curl 可能会回移安全补丁，但通常不会增加新参数。

查看页面和下载文件

--output-dir 从 curl 7.73.0 才有。CentOS 8 的 7.61.1 会报未知参数。

重定向

-L 会跟随 301/302/303/307/308。其中 301、302、303 会把 POST 改成 GET；307 和 308 保持原来的方法。

-d 本身就会发 POST。不要再加 -X POST，否则每一次重定向都会被强制成 POST。

指定方法和请求体

curl 7.82.0 起可以用 --json，它会设置 Content-Type: application/json、Accept: application/json 并按 POST 发送。7.61.1 没有这个参数。

上传文件

-F 会自动加上带 boundary 的 Content-Type: multipart/form-data。再手写一个不带 boundary 的 Content-Type，服务端经常解析失败。

在脚本里使用

这条命令把正文打到标准输出。要落盘时再加上 -o。

  • -s 关掉进度和报错，-S 在静默时仍把错误打出来。两个一起用，脚本输出里只留下真正的失败信息。

  • -f 遇到 404、500 这类 HTTP 错误时，不把错误页正文打出来，并且以非 0 状态退出。脚本可以直接看 $?。

证书校验失败

先看本机时间

HTTPS 会检查证书有效期。本机时间快了或慢了，也会报证书过期，或者 certificate is not yet valid。先执行 date 看时间是否正确。

按状态码判断失败，以及统计耗时

-I 发的是 HEAD。有的服务对 HEAD 和 GET 返回不同状态码，检查页面是否可用时用 GET，也就是不要加 -I。

--retry 只对超时和部分临时错误重试。curl 7.61.1 支持的 HTTP 状态包括 408、500、502、503、504；HTTP 429 从 7.67.0 起才会触发重试。连接被拒绝要另加 --retry-connrefused。

-m 是单次传输的上限。--retry-max-time 会在开始下一次重试前检查累计时间，但不会中断已经开始的那一次请求，因此它不是严格的整体超时；实际总耗时可能超过设置值。需要严格控制脚本总运行时间时，还应由外层的 timeout 或任务调度器限制。

-w 还可以输出这些字段：

  • %{time_namelookup}、%{time_connect}、%{time_appconnect}、%{time_pretransfer}、%{time_starttransfer}、%{time_total}：见下面的计时说明，都是从请求开始算的累计时间

  • %{size_download}、%{size_upload}：下载、上传的字节数

  • %{url_effective}：跟随重定向之后的最终 URL

  • %{content_type}：响应的 Content-Type

  • %{remote_ip}：连上的服务器 IP

下面这组时间是累计值。time_connect 里已经包含 DNS，time_starttransfer 里已经包含连接、握手和等到首字节的全部时间。

字段 含义（从请求开始累计）
%{time_namelookup} DNS 解析完成
%{time_connect} TCP 连接完成，已包含 DNS
%{time_appconnect} TLS 握手完成，已包含 DNS 和 TCP。纯 HTTP 时为 0
%{time_pretransfer} 即将把请求发给服务器
%{time_starttransfer} 收到响应的第一个字节
%{time_total} 本次传输结束

某一段花了多久，用相邻两项相减：

  • DNS = time_namelookup

  • TCP = time_connect - time_namelookup

  • TLS = time_appconnect - time_connect（纯 HTTP 时 time_appconnect 为 0，这一项跳过）

  • 请求发出到首字节 = time_starttransfer - time_pretransfer。有请求体时，这段还包含上传请求体的时间，不能全部视为服务端处理耗时

  • 传输正文 = time_total - time_starttransfer

按上面的样例，正文传输大约是 2.364 秒，等到首字节几乎可以忽略。

源码安装

有的系统没装 curl：yum install curl -y。需要较新版本时再从源码装。不要复制旧文章里的固定版本号：旧版 curl 可能包含已经公开的安全漏洞。安装前到 curl releases 选择当前版本，并按 curl 签名说明 校验下载文件的签名或摘要。

装到 /usr/local 后，/usr/local/bin/curl 会和系统的 /usr/bin/curl 并存。动态库版本对不上时，会出现 error while loading shared libraries。只是临时试用时，把下面的安装前缀改成 $HOME/.local，避免碰系统自带的 curl。

POST、Header 和 Cookie

wget 多数时候用来做 GET 下载，也可以带请求体和 Header。

镜像整个网站

  • --mirror：等同于 -r -N -l inf --no-remove-listing。也就是递归下载、按时间戳跳过没有更新的文件、不限制深度，并保留 FTP 目录列表生成的 .listing 文件。-l inf 表示深度没有上限。

  • --convert-links：下载完成后，把页面里的链接改成本地相对路径，方便离线打开。

  • --adjust-extension：服务器返回的是 HTML，但 URL 没有 .html 时，补上合适的扩展名。

  • --page-requisites：下载页面显示要用到的图片、CSS 等。默认不跨主机，其他域名上的资源要再加 -H（--span-hosts）。

  • --no-parent：不访问起始 URL 所在目录的上级目录。

http 命令是什么（HTTPie 简介）

HTTPie 是一个面向人的命令行 HTTP 客户端，用来调试 API。安装后有两个命令：http 发请求，https 强制走 HTTPS。

和 curl 相比，它的输出带颜色、语法更接近自然语言，并且会自动处理 JSON 的 Content-Type 和格式化。curl 仍然更适合写进脚本，也更常见于服务器上。

HTTPie 的会话文件会以明文保存认证信息、Cookie 和自定义 Header。不要在会话中保存敏感信息；确实需要时，应保护好 HTTPie 配置目录及会话文件的读取权限。

特性 HTTPie（http） curl
可读性 输出带颜色，默认排版友好 更接近协议本身
JSON 自动设置 Content-Type 并格式化输出 自己设置 Header，并用 --data-binary 发送
请求怎么写 接近 方法 URL 字段=值 由 -H、-d、--data-binary 这些参数拼出来
调试 REST API 交互时少打很多参数 同样能做，命令更长
脚本和服务器 需要单独安装，CentOS 上一般走 EPEL 多数系统已经带有，退出码和 -w 更适合脚本
